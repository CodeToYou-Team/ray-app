# AGENTS.md

## Commands

- `pnpm dev` - Start dev server (http://localhost:3000)
- `pnpm build` - Production build
- `pnpm start` - Start production server
- `pnpm lint` - ESLint
- `pnpm typecheck` - `tsc --noEmit`

> `pnpm typecheck` has two staleness traps:
>
> 1. It reads the route types Next generates under `.next/**/types`. After moving or
>    renaming routes those go stale and it reports phantom errors for files that no
>    longer exist. Run `pnpm build` (or delete `.next`) first.
> 2. `incremental: true` writes `tsconfig.tsbuildinfo`. After changing a
>    `compilerOptions` value it can keep reporting errors from the old settings.
>    Delete `tsconfig.tsbuildinfo` if an error survives a fix that should have
>    resolved it.

## Architecture

- `/app/(app)` - Route group holding every in-app page behind one shared shell layout.
  The group name is not part of the URL: `/dashboard` is still `/dashboard`.
- `/app/(app)/layout.tsx` - The only app shell (sidebar + header + main).
- `/components/ui` - Vendored shadcn/ui primitives. Regenerated by the shadcn CLI —
  do not hand-edit; some React Compiler lint rules are turned off for this folder in
  `eslint.config.mjs`.
- `/components/dashboard`, `/components/finanzas`, `/components/layout`
- `/lib/nav.ts` - Single route registry. Feeds both the header title and the sidebar
  tree. Adding a route means adding an entry here, or the header warns in dev.
- `/lib/format.ts` - `formatMoney` (currency-aware), `formatDate`, `getPercentChange`.
- `/lib/db` - Drizzle schema, connection, and `withTenant()`. Server-only.
- `/lib/authz` - `requireSession` / `requireTenant` / `requireCapability`, plus the
  role-to-capability map. Every Server Action starts with one of these.
- `/lib/catalogs` - The polymorphic catalog registry, queries and actions.
- `/lib/finanzas` - `register.ts` holds the transaction/inventory logic and takes an
  explicit `{tenantId, userId}`; `actions.ts` is a thin `"use server"` wrapper that
  enforces the capability first. The split exists so the money logic is testable
  without faking a Supabase session — never call `register.ts` from a route.
- `/lib/inventario/stock.ts` - Stock is `SUM(delta)`, never a stored column.
- `/lib/money.ts`, `/lib/currencies.ts` - Exact decimal arithmetic and the closed
  currency list. Currency columns are `varchar(10)`: stablecoin tickers (USDT, USDC)
  are 4 characters, not 3.
- `/drizzle` - Migrations. RLS policies, triggers and the `app_user` role live in
  hand-written `.sql` files there, not in the Drizzle schema.
- `/tests` - Vitest. DB tests skip silently without `TEST_DATABASE_URL`, so a green
  run proves nothing on its own — check the skip count. They run against a REMOTE
  Postgres, so `testTimeout` is 30s: that is network latency, not slow code.
  That also makes the full run intermittently flaky: when the remote is slow the
  whole suite stretches (seen: 776s against a usual ~330s) and a single DB test
  trips the 30s timeout. Before chasing such a failure, re-run that file alone
  and compare the suite's total duration — a pass in isolation means the clock,
  not the code.

## Plan of record

`docs/plan_arquitectura_v2.md` is the current plan; `docs/plan_arquitectura_multitenant.md`
is superseded but remains the reference for infrastructure (Supabase pitfalls, RLS,
`withTenant`, schema evolution rules). Key decisions:

- Multi-tenant on Supabase Postgres, Drizzle server-side only, RLS as defence in depth.
- The project's **Data API (PostgREST) is disabled on purpose**. `supabase-js` is used
  for authentication only; `createSupabaseServerClient()` returns a type narrowed to
  `{ auth }`, so reading data through it is a compile error. All data access goes
  through Drizzle + `withTenant()`. Supabase's "automatic RLS" event trigger is on, so
  a new table without policies fails closed instead of leaking.
- Fixed domain schema. The only dynamic part is custom fields on products/services,
  stored in a `custom jsonb` column keyed by the field's **immutable slug**.
- Catalogs (categories, payment methods) are ordinary relational rows in one
  polymorphic `catalog_items` table, not dynamic schema.
- **Totals are kept separate per currency and are never summed across them.**
  The one conversion that exists is per operation: when catalog prices are in a
  different currency than the payment method, the user types the rate, it is
  stored on the transaction (`exchange_rate` + `base_currency`), and the line
  items are stored already converted. There is no rate table and no external
  rate lookup — re-reading a January sale must always give the same number.
  All items in one operation must share a single currency; two would need two
  rates and the total would belong to neither.
  The `exchange_rates` table is a *suggestion* source only — the rate the owner
  declares in Ajustes for a currency pair. It is never read when computing a
  stored amount; it only pre-fills the form, and the derived "last rate used"
  (`lastExchangeRates()`) fills in when no rate is configured. Changing or
  deleting a row there must never move a figure that is already recorded.
- Money is `numeric` in Postgres and `string` in TypeScript. Never a JS `number`,
  never `z.coerce.number()`. All arithmetic goes through `lib/money.ts`, which works
  on scaled `BigInt`s; its rounding is verified to match Postgres `round(x, 2)` so the
  `transaction_items.subtotal` CHECK never rejects a row the app computed. That BigInt
  use is why `tsconfig` targets ES2022 — do not lower it.
- Stock is `SUM(delta)` over an append-only `stock_movements` table, never a mutable
  column.
- Catalog options and custom fields are archived, never deleted.

## Conventions

- Language: Spanish throughout (UI, metadata, content, code comments).
- Theme: `next-themes` with light/dark via CSS variables.
- Fonts: Plus Jakarta Sans + IBM Plex Mono (via next/font/google).
- Forms: react-hook-form + Zod. Import from `zod`, not `zod/v4`.
- Reads go through RSC; writes go through Server Actions, each with its own
  authorization check. Never put authorization in `proxy.ts`.

## Important

- No test setup configured yet.
- No pre-commit hooks.
- **Never overwrite `.env.local`.** It holds credentials that only the user has, and
  there is no backup — VSCode local history excludes `.env*`. Edit it line by line
  (targeted regex replace, the way `scripts/bootstrap-app-user.ts` rewrites only the
  `DATABASE_URL` line), never write the whole file over an existing one. Checking
  "does a placeholder remain?" is NOT a safe emptiness test: a partially filled file
  still contains placeholders. Test whether the specific line you intend to touch is
  still a placeholder.
- **There is deliberately no `.env.example`.** `.gitignore` excludes every `.env*`, so
  one more file that looks like a template is one more place a real credential can
  leak by accident. `lib/env.ts` is the source of truth for which variables exist and
  why each one is shaped the way it is; `docs/setup.md` says where each value comes
  from. Keep both current instead of reintroducing a template.
- `pnpm-workspace.yaml` blocks package build scripts on purpose. If pnpm asks about a
  new one, decide explicitly rather than leaving the placeholder — an unresolved entry
  makes every `pnpm <script>` fail.
- `pnpm lint` is expected to be completely clean. The React Compiler warnings about
  react-hook-form's `watch()` are gone: those forms were replaced.
- **UUIDv7 is time-ordered**, so ids generated in the same millisecond share a long
  prefix. Test fixtures that derive a unique value from `id.slice(0, 8)` produce
  *identical* values for every user created in one `beforeAll`. Slice from the end
  (`id.slice(-12)`) when a fixture needs distinct emails or slugs.
- There is no mock data left. Every page reads from Postgres; if a screen has nothing
  to show it renders an empty state, not invented rows.
